# 日记本页面 · 设计稿（2026-11-02）

> 状态：草案，待主人确认。确认后才进入实现计划。
> 范围：v0.2 的「可翻看的日记本」；不改写日记内核的确定性边界。

## 1. 意图

给陪伴型 agent 的日记加一个**能被主人翻看**的页面。它不是管理面板，也不是数据看板，而是「它私藏的一本本子」——主人只读，偷看这件事本身会成为叙事的一部分。

写日记的仍然是服务器上 24 小时在线的那个 AI；主人不在 DSH 里养鱼，但可以在 DSH 里偷看。

## 2. 目标 / 非目标

**目标**

- 一天一页，按 scope（群 / 私聊）分小节，可按时间翻。
- 手写质感：纸、墨、歪歪扭扭的字。
- 简笔画画「今天真实出现的那件东西」，跟着对应句子走。
- 照片由 AI 从当天素材里挑，像贴上去的拍立得。
- 偷看计数，作为事实交给 AI；它不进日记，只在聊天里旁敲侧击。
- 能在服务器的 web profile 里跑。

**非目标**

- 不在 QQ 里设计「向 AI 索要日记」的入口（那是点单，不是偷看）。
- 不做上传 / 编辑 / 删除；主人没有任何写入口。
- 不把整个 DSH 暴露到公网。
- 不让插件调用模型或生成位图（简笔画由 AI 写结构化线条，客户端渲染）。

## 3. 部署拓扑（决定一切的前提）

```
QQ ←→ qq-bridge（独立进程，SnowLuma SDK）
          │ apiproxy（127.0.0.1:3080）
          ▼
   服务器 dsh web（web profile，24h）
     ├─ 会话 / 工具 / qq-bridge 的对话
     └─ dsh-whale-notes（写日记 + 本子页面）
          └─ $DSH_HOME/journal/（entries / media / peek）
```

- 写日记的 AI 在**服务器**的 DSH 上，不在本地。
- 本地 desktop DSH 只用于开发与预览；看不到服务器的日记，除非主动拉取。
- 偷看路径（README 要写清楚）：
  1. **SSH 隧道**（推荐，已有 `open-tunnels.sh`：13080 → 服务器 3080），浏览器打开 `http://127.0.0.1:13080`，进本子页；服务端计数。
  2. **局域网 / 反代**（主人不在同一台机器时）——需要额外配置，默认不做。
  3. **本地只读镜像**（运维预览）：把 `$DSH_HOME/journal` 拉到本地用 viewer 看；**不算偷看**，除非镜像端显式上报 peek。
- 明确警告：`dsh web` 是完整的 agent 控制权，不是只读日记；不要把 3080 直接暴露公网。

## 4. 页面

- 版式：横线作业本（白纸、蓝线、红边），日期手写，右下折角。后续可换成牛皮纸/旧本子，但 v0.2 只做一版。
- 正文：16px / 28px 行高；字体「贤二体」（骨架）+ 逐字抖动（旋转 ±4–7°、位移 ±2–3.5px、缩放 ±5–8%，按日记 id 做种子，保证同一篇每次一致）+ 很轻的纸面位移滤镜。
- 简笔画：
  - AI 写 `120×80` 的线条 SVG（只允许 path/circle/line，`fill:none`）。
  - `anchor`：引用原句里的一个片段；`side`：`left | right | inline`。
  - 渲染时插到锚点那句旁边；**放不下、锚点找不到就不画**（不翻转、不缩小、不挤到页脚）。
- 照片：
  - AI 从当天可用照片里挑 0–N 张，`anchor` / `side` 规则同上。
  - 复制进 `journal/media/`，页面按拍立得样式呈现，可带一句短注。
- 空页成立：没有画、没有照片，只有字。

## 5. 偷看机制

- 主人打开某天页面 → 客户端 `POST /journal/peek`（date、scope、来源）→ 服务端写 `peek.jsonl`。
- 同一页 10 分钟内重复打开不重复计。
- 聊天会话通过只读工具拿到事实：总次数、按天次数、上次时间；**写日记的会话不注入**。
- AI 不在日记里提这件事；只在聊天里旁敲侧击（是否提、怎么提、信不信主人的否认，全由各 AI 的性格决定）。
- 本地镜像拉取默认不计数（运维预览）。

## 6. 数据模型

`entries.jsonl` 保持追加 + 按 id 折叠，新增可选字段（旧数据照常读）：

```jsonc
{
  "v": 1,
  "id": "j_...",
  "date": "2026-11-02",
  "scope": "group:...",
  "text": "...",
  "mood": "安静",
  "refs": [12, 13],
  "doodle": {
    "svg": "<path d=\"...\"/>",     // 只存内部节点，渲染时再包 <svg>
    "anchor": "楼下那只橘猫",
    "side": "right"
  },
  "photos": [
    { "file": "media/2026-11-02/ab12.jpg", "anchor": "她发的晚霞", "side": "right", "caption": "她发的晚霞" }
  ],
  "status": "active"
}
```

- `media/` 只存被选中的照片副本；原图仍在桥接侧。
- `peek.jsonl`：`{ "ts": ..., "date": "2026-11-02", "scope": "...", "source": "web" }`。
- 不新增数据库；规模仍是每天几条。

## 7. 工具契约

| 工具 | 变化 |
|---|---|
| `journal_write` | 新增可选 `doodle`、`photos`；其余不变；超上限/超条数仍报错 |
| `journal_read` / `journal_search` | 返回里带 `doodle` / `photos` 摘要（不返回整段 SVG，避免刷上下文） |
| `journal_digest` | 新增「当天可用的照片」列表（路径、时间、谁发的）；**不含**偷看数据 |
| `journal_audit` | 不变 |
| `journal_archive` | 不变 |
| `journal_peek`（新增） | 只读事实：次数、按天、上次时间；供聊天会话使用 |

插件仍然不调模型、不联网；SVG 净化与照片复制在本地完成。

## 8. UI 集成

- 服务器 web profile 里通过 `ctx.webServer` 注册 `/journal` 前缀路由，直接提供只读页面（原生 HTML/CSS/JS，不做 client 插件与打包链）。
- 页面只读：没有编辑/删除/上传按钮；只有翻页、选某天、按 scope 过滤。
- 只读接口：`GET /journal/api/days`、`GET /journal/api/day?date=...&scope=...`、`GET /journal/media/*`、`POST /journal/api/peek`（唯一的写入口）。
- 渲染与逐字抖动在浏览器端；`seed = entry.id`，保证同一篇每次一致。
- headless / SDK profile 没有 `webServer`，只少一个页面，工具照常。
- 第一版不做：QQ 图片、整本 PDF、搜索 UI、周检报告页。

## 9. 安全

- SVG 白名单：只允许 `path / circle / line / polyline`，禁 `script / foreignObject / image / use / href`，长度上限。
- 媒体路径做目录穿越校验，只允许 `journal/media/` 下的文件。
- peek 接口只接受本机/受信来源；不做公开写入。
- 页面无任何写操作；主人的写权限为零。
- README 明示：不要把 `dsh web` 暴露公网。

## 10. 风险与开放问题

- **字体授权**：贤二体来自商免合集，发布前必须核对 LICENSE 原文；备选 OFL 的「小赖」「悠哉」但都不够歪。
- **可读性**：正文抖动调低（0.45 左右），标题/日期可以更歪；上线前要用真实长度的日记读一遍。
- **锚点脆弱**：编辑日记后锚点可能失效——按设计不画，不报错。
- **照片来源**：需要桥接把当天图片路径给 digest（桥接侧改动，本仓库只消费）。
- **服务器渲染**：v0.2 只做 Web 页面，不生成 QQ 图片；以后要发图再加 SVG → PNG。
- **多 scope**：一本本子按小节分，还是按 scope 分本？v0.2 先一本多小节，翻页时可按 scope 过滤。
